# Renforcement anti-publicite - 0.77.0-dev

## Contexte

Retour utilisateur : apres etre alle sur un site, il s'est retrouve sur « une
pub de jeux impossible a l'enlever ». Diagnostic : le bloqueur reseau filtre les
requetes dans les pages mais laissait passer (1) les popups `window.open` (chaque
popunder = un onglet), et (2) les navigations de l'onglet vers un domaine de pub
(clic detourne). Plan valide par « Go ».

## Changements

- `PopupPolicy.cs` (nouveau, pur, teste) : `Decide` (Allow / BlockAutomatic /
  BlockAdDomain), `IsLikelyAuthenticationPopup` (protege OAuth/login).
- `MainWindow.AdShield.cs` (nouveau partiel) : `BlockPopupIfUnwanted`
  (NewWindowRequested), `ShouldStrictBlockNavigation` + barre `AdBlockedBar`
  « Continuer quand meme » (NavigationStarting), `RegisterExplicitNavigation` /
  `_explicitNavigationUris` (les adresses demandees par l'UI ne sont jamais
  bloquees), `_adContinueRoots` (autorisation de session).
- `MainWindow.Navigation.cs` : appel popup dans `NewWindowRequested` (avant
  creation d'onglet) ; blocage strict dans `NavigationStarting` (apres le
  nettoyage URL, en reportant la legitimite explicite sur l'URL nettoyee) ;
  `RegisterExplicitNavigation` sur les navigations `NavigateTabView` ; masquage
  de la barre dans `ActivateTab` et au depart de navigation.
- `PrivacyEngine.RecordManualBlock` + surcharge `RecordBlock(id,name,...)` :
  compte popups/redirections dans le bouclier.
- `NetworkBlockerModule.IsWhitelisted`.
- `FilterListManager` : + `liste_fr` + `ublock-annoyances`.
- `UiSettings` : `PopupBlockerEnabled`, `StrictAdBlockEnabled` (defaut true).
- `MainWindow.Privacy.cs` / `.Settings.cs` / XAML : 2 interrupteurs
  Confidentialite + chargement.
- XAML : `AdBlockedBar` (Row 10), `BrowserHost` -> Row 11.
- Version : `0.77.0-dev`.

## Verification (skill verify)

- Build WinUI OK ; `dotnet test` : 365/365 verts (12 nouveaux `PopupPolicyTests`
  couvrant popunder auto, clic vers domaine pub, site normal, about:blank,
  fenetres d'auth, whitelist, bloqueur desactive, priorite pub sur geste).
- **Live (UIA + clic souris natif, profil isole, mode invite)** sur une page de
  test locale (`popup-test.html` : popunder auto au chargement + boutons
  window.open pub/normal) :
  1. Chargement → popunder `window.open('https://example.org/popunder')` sans
     geste → trace `Popup blocked (BlockAutomatic)`, la page affiche
     « popunder auto retour: null (bloque cote script) », aucun onglet parasite
     (capture `077-popups.png`).
  2. Clic natif sur « Popup domaine pub (clic) » (`window.open('https://doubleclick.net/...')`)
     → trace `Popup blocked (BlockAdDomain)`, aucun onglet parasite.
- Coordonnees du clic natif : repere fenetre reel = coord image affichee x1.44
  (piege : ne pas cliquer avec les coord de l'image reduite).

## Notes

- Le comptage d'onglets via UIA a retourne 0 sur la page file:// (contenu
  WebView2 non expose) : sans consequence, la preuve du blocage vient de la
  trace + du retour `null` cote page + de l'absence d'onglet a l'ecran.
- Blocage strict volontairement limite aux domaines entiers (pas aux regles de
  chemin) pour eviter les faux positifs.
